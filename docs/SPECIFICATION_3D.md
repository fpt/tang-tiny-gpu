# 3D GPU 仕様書 (アプリケーション開発者向け)

Tang Nano 20K の **3D GPU のビットストリーム** を、ホスト (RP2350 など) のプログラムから使うための仕様。
三角形を投げて、Gouraud・テクスチャ・Z・半透明で描く、PS1 程度のタイルベースの遅延描画 (TBDR) の GPU。
2D のレイヤ (タイルの面・スプライト・Mode 7) を持つ VDP は別のビットストリームで、仕様は [SPECIFICATION.md](SPECIFICATION.md)。
2 つはフラッシュに一緒に置き、ホストが `RECONFIG` で入れ替える (2 章)。

正確な定義は RTL ([`gpu.sv`](../rtl/vdp/gpu.sv)、[`raster3d.sv`](../rtl/gpu3d/raster3d.sv)、[`tri_setup.sv`](../rtl/gpu3d/tri_setup.sv)、
[`tri_engine.sv`](../rtl/gpu3d/tri_engine.sv)、[`tile_engine.sv`](../rtl/gpu3d/tile_engine.sv)) と、参照モデル
([`raster.py`](../tools/harness/raster.py) が描く規則、[`gpu_model.py`](../tools/harness/gpu_model.py) がコマンド列から画像と CRC を作る)。
参照モデルは RTL と同じ画をピクセル単位で作る (CRC が一致する) ので、ホスト側のテストの期待値に使える。食い違いがあれば RTL が正しい。
中の作り (TBDR の段、実装で分かったこと) は [ARCHITECTURE.md](ARCHITECTURE.md) の 8・10 章。

## 1. 概要

- 論理画面は **320 x 240**、RGB565。出力は縦横 2 倍の 640 x 480 @ 60Hz (HDMI / DVI)
- 表示は SDRAM のフレームバッファ 2 面 (描く面と表示する面を `SWAP` で入れ替える) と背景色・透過色だけ。タイルの面・スプライト・8bpp の表示・
  ライトマップ・Mode 7・音は**ない** (VDP のビットストリームにある)
- ホストは三角形を**画面の座標**で送る (頂点の変換・照明・クリップ・並べ替えはホストの仕事。PS1 の CPU + GTE の役)。GPU は描く規則 (5 章) どおりに
  ピクセルを塗る
- 描き方は**タイルベースの遅延描画**: `BEGIN_SCENE` と `END_SCENE` のあいだの三角形をためておき、`END_SCENE` で 32 x 32 のタイル (80 個) ごとに
  オンチップのメモリ (色・Z) で描いてから SDRAM に書き出す。Z と半透明の読み書きが SDRAM に出ない
- 2D のコマンドのうち RGB565 で描くもの (`CLEAR` `FILL_RECT` `POINT` `DRAW_LINE` `UPLOAD` など、4 章) もある

```text
ホスト ──SPI (本番は HSTX)──► レジスタ ──► コマンド FIFO (2,048 ワード) ──► GPU
                                                                 │ 2D のコマンド ─────────► SDRAM の描く面
                                                                 └ TRI ─► セットアップ・ビニング (SDRAM のパラメータ)
                                                                          END_SCENE ─► タイルごとに描く (オンチップの色・Z) ─► SDRAM の描く面
SDRAM の表示する面 ──► 表示 (背景色・透過色) ──► 640x480
```

| 資源 | 大きさ | 書き方 |
| --- | --- | --- |
| SDRAM | 8MiB (2M ワード x 32bit) | `UPLOAD`、描くコマンド |
| CLUT | 256 色 (RGB565) | `CLUT_WRITE` |
| コマンド FIFO | 2,048 ワード | SPI の `CMD` (0x30) |

## 2. ビットストリームの切り替え

フラッシュに 2 つのビットストリームを置く。電源を入れると VDP が立ち上がる。

| 番地 (フラッシュ) | ビットストリーム | `VERSION` (0x7F) | 次 (multiboot) |
| --- | --- | --- | --- |
| `0x000000` | VDP | `0x01` (bit7 = 0) | `0x100000` |
| `0x100000` | 3D GPU | `0x81` (bit7 = 1) | `0x000000` |

- **`RECONFIG` (0x7C) に `0xA5` を書くと**、FPGA が RECONFIG_N を自分で Low にして、相手のビットストリームを読み直す。約 **1.7 秒**。
  そのあいだ SPI は応答しない (`ID` が `0x5A` に戻るまで待つ)。`VERSION` の bit7 でどちらが動いているか分かる
- 切り替えると、どちらのビットストリームもレジスタは既定に戻る。**SDRAM の中身 (テクスチャ・フレームバッファ) は保証しない**ので、ホストが送り直す
- フラッシュへの書き込みは開発環境の `make flash` (VDP と 3D GPU の組)。ハーネスの `harness.py` は、要るビットストリームが動いていなければ自分で切り替える

## 3. ホストとの接続とレジスタ

SPI の形式、IRQ / VSYNC / HEARTBEAT / RESET の線は VDP と同じ ([SPECIFICATION.md](SPECIFICATION.md) の 2 章)。違うところだけ書く。

### レジスタ

| アドレス | 名前 | R/W | 内容 |
| --- | --- | --- | --- |
| `0x00` | `STATUS` | R | bit0: VBLANK 中、bit1: エラー (SPI のフレームエラー。読むとクリア) |
| `0x01` | `CONTROL` | RW | **bit3: フレームバッファを表示 (0 ならテストパターン)**、bit2: IRQ 許可 (VBLANK)、bit4: IRQ ピンを READY に。既定 0 |
| `0x04` | `FRAME_COUNT` | R | フレームカウンタの下位 8bit |
| `0x05`〜`0x08` | `FRAME_CRC` | R | 直前のフレームの表示の CRC-32 (12 章) |
| `0x09` | `UNDERFLOW` | R | 表示に間に合わなかったライン数 (飽和) |
| `0x0A`〜`0x0F` | `CRC_FRAME` `MARK_CRC` | R | VDP と同じ |
| `0x30` | `CMD` | W | コマンドのポート (4 バイトで 1 ワード、リトルエンディアン) |
| `0x40` | `GPU_STATUS` | R | bit0: 実行中、**bit1: エラー** (知らないコマンド、外したコマンド、シーンやタイルの上限を超えた三角形。読むとクリア)、bit2: FIFO があふれた (読むとクリア) |
| | | W | bit0 に 1: FIFO を空にする |
| `0x41`〜`0x42` | `GPU_FREE` | R | FIFO の空き (ワード数)。最大 2,048 |
| `0x44`〜`0x45` | `FB_BASE` | RW | 表示する面の先頭 (1KiB 単位)。既定 0 |
| `0x46`〜`0x47` | `DRAW_BASE` | RW | 描く面の先頭。既定 256 (= バイト `0x040000`) |
| `0x48`〜`0x49` | `BG_COLOR` | RW | 背景色 (RGB565) |
| `0x4A` | `LAYER_CTRL` | RW | bit0: フレームバッファを出す、bit1: 透過色を有効 |
| `0x4C`〜`0x4D` | `BITMAP_KEY` | RW | 透過色 (RGB565) |
| `0x7C` | `RECONFIG` | W | `0xA5` でビットストリームを切り替える (2 章) |
| `0x7D` | `SCRATCH` | RW | リンクの確認用 |
| `0x7E` | `ID` | R | `0x5A` |
| `0x7F` | `VERSION` | R | `0x81` (bit7 が 3D GPU の印) |

- **起動したら `CONTROL` に `0x08` (READY を使うなら `0x18`) を書く**
- `0x10`〜`0x2F` は SDRAM の 1 ワードの読み書き (テスト用)。3D GPU のビットストリームには SDRAM の BIST がない (`MEM_STATUS` bit4 = 1)
- 流量の制御は VDP と同じ (READY の線か `GPU_FREE`)。FIFO が 2,048 ワードあるので、`END_SCENE` でタイルを描いているあいだに次のフレームのコマンドを
  2,048 ワードまで受けておける

### `REG_WRITE` で書くレジスタ

`REG_WRITE` `[0x09, reg(8), value(16)]` は FIFO の順に効く (ラインの合成を始めるときに取り込む)。3D GPU で意味があるのは次だけ:

| 番号 | 名前 | 内容 |
| --- | --- | --- |
| 0 | `BG_COLOR` | 背景色 (RGB565) |
| 1 | `LAYER_CTRL` | bit0: フレームバッファを出す (既定 1)、bit1: 透過色を有効 |
| 2 | `BITMAP_KEY` | 透過色 (RGB565) |
| 27 | `Z_BASE` | Z バッファの先頭 (13bit、256 ワード単位)。既定 `0x0E00` (= バイト `0x380000`)。ピクセル (x, y) の z はワード `(Z_BASE + y) * 256 + x / 2` の 16bit (下位が偶数の x) |

VDP の面・スプライト・音・Mode 7 の番号 (3〜26、32〜50) は受け付けるが何も起きない。28〜31 と 51〜 はエラー。`BITMAP_FMT` (22) は 0 (RGB565) のまま使う。

## 4. コマンド

コマンドは 32bit ワードの列。先頭ワードの `[31:24]` がコマンド番号。座標の組は `{y[15:0], x[15:0]}` (下位が x)。FIFO の順に 1 つずつ実行する。

| 番号 | コマンド | ワード数 | 概要 |
| --- | --- | --- | --- |
| `0x00` | `NOP` | 1 | 何もしない |
| `0x01` | `CLEAR` | 1 | 描く面の全体を `[15:0]` の色で塗る (クリップ矩形は効かない) |
| `0x02` | `FILL_RECT` | 3 | 矩形 |
| `0x03` | `SWAP` | 1 | 表示する面と描く面を入れ替える (表示が取り込むまで後続を待たせる) |
| `0x04` | `UPLOAD` | 2 + n | SDRAM のワードアドレスから n ワード書く (テクスチャを送る) |
| `0x05` | `POINT` | 2 | 1 ピクセル |
| `0x06` | `DRAW_LINE` | 3 | 線 |
| `0x07` | `CLIP` | 3 | クリップ矩形 (2D のコマンドと**シーンの外の** `TRI` に効く。シーンの `TRI` には記録したときの矩形) |
| `0x09` | `REG_WRITE` | 1 | 3 章の表 |
| `0x0A` | `WAIT_LINE` | 1 | ライン n まで待つ |
| `0x0B` | `WAIT_VBLANK` | 1 | 次のフレームのライン 0 まで待つ (印を付けられる) |
| `0x20` | `TRI` | 4〜13 | 三角形 (5 章) |
| `0x21` | `SET_TEX` | 2 | 今のテクスチャ (6 章) |
| `0x24` | `CLEAR_Z` | 1 | Z バッファ全体 (320 x 240 x 16bit) を `[15:0]` で塗る |
| `0x25` | `BEGIN_SCENE` | 1 | シーンを始める (7 章) |
| `0x26` | `END_SCENE` | 1 | シーンを描く (7 章) |
| `0x28` | `CLUT_WRITE` | 1 + ⌈n/2⌉ | CLUT を書く (6 章) |

- 2D のコマンドの形と規則は VDP と同じ ([SPECIFICATION.md](SPECIFICATION.md) の 4 章)。色は RGB565 だけ
- **`BLIT` (0x08)・`STRETCH_BLIT` (0x0E) と 8bpp の面への描画はない** (エラーが立つ)。画像はテクスチャの四角形 (`TRI` 2 つ) で描く
- `VRAM_WRITE` `PAL_WRITE` `OAM_WRITE` `LIGHT_WRITE` は読み飛ばされる (書き先がない)
- 知らない番号はエラーを立て、1 ワードのコマンドとして読み飛ばす

## 5. 三角形 (`TRI`)

```text
[0x20, flags(8), color(16)]   頂点 0 の {y, x}、[{r, g, b}]、[{z}]、[{v, u}]   頂点 1 …   頂点 2 …
```

| flags | 意味 |
| --- | --- |
| bit0 | Gouraud: 頂点ごとに `{r, g, b}` (`[23:16]` `[15:8]` `[7:0]`) を補間する。なければ `color` (RGB565) の単色 |
| bit1 | テクスチャ: 頂点ごとに `{v, u}` (`[31:16]` `[15:0]`、10.6 = 1/64 テクセル) を補間し、テクセルを貼る (6 章) |
| bit2 | 半透明: 描く面の色と混ぜる。式は `[5:4]` |
| bit3 | Z: 頂点ごとに `{z}` (`[15:0]`) を補間し、Z テストする |
| `[5:4]` | 半透明の式 (下) |

頂点ごとのワードは `{y, x}` → (Gouraud なら) 色 → (Z なら) z → (テクスチャなら) uv の順。1 三角形は 4 (単色) 〜 13 ワード (Gouraud + Z + テクスチャ)。

### 描く規則 (同じ絵を出す規則。正は `raster.py`)

- 頂点の x, y は**符号付き 12.4** (1/16 ピクセル)。**-512..+831 ピクセル** (ガードバンド) の中に収める。外にはみ出す三角形はホストが切る
- ピクセル (px, py) の中心 (px + 0.5, py + 0.5) が三角形の中なら描く。辺の上は**上左の規則** (上の辺と左の辺の上だけ中)。辺を共有する三角形に隙間も重なりもない。
  矩形を 2 つに割った三角形は `FILL_RECT` と同じピクセルを塗る
- どちらの向き (時計回り / 反時計回り) も描く (裏面を捨てるのはホスト)。面積 0 は描かない。クリップ矩形の外は描かない
- 属性 (r, g, b, z, u, v) は頂点の値の**画面で線形の**補間 (遠近補正はない)。固定小数点 12bit、勾配は面積の逆数 (17bit の仮数) から作るので、
  頂点の値と少しずれることがある (切り捨て)。色は 0..255、z は 0..65535 に切る。色は RGB565 に切り捨て
- **Z** (bit3): `z < Z バッファ` なら通り、色と z を書く。**同じ z は先に描いたものが勝つ**。Z なしの三角形は Z バッファを読まず書かない
- **テクスチャ** (bit1): テクセルの色 0 (RGB565 の `0x0000`) は**透明** (色も Z も書かない)。Gouraud なら頂点の色で**変調**する (128 = 1 倍):
  `R = min(31, texR * r >> 7)`、`G = min(63, texG * g >> 7)`、`B = min(31, texB * b >> 7)`。Gouraud でなければテクセルの色そのまま
- **半透明** (bit2): 描く色 F (テクスチャ・変調のあと) と描く面の色 B を RGB565 の成分ごとに混ぜる。Z があれば Z テストはするが **Z は書かない**

| `[5:4]` | 式 |
| --- | --- |
| 0 | 平均 `(B + F) >> 1` |
| 1 | 加算 `min(最大, B + F)` |
| 2 | 減算 `max(0, B - F)` |
| 3 | 1/4 加算 `min(最大, B + (F >> 2))` |

- 三角形は**投入順**に描く (並べ替えない)。半透明は不透明を全部送ってから、奥から手前に送る

## 6. テクスチャ

**`SET_TEX`** `[0x21, -, fmt(2) clut_off(8) wl(4) hl(4)]` `base`

| フィールド | 位置 | 意味 |
| --- | --- | --- |
| fmt | `[17:16]` | 0 = 16bpp (RGB565)、1 = 8bpp (CLUT)、2 = 4bpp (CLUT) |
| clut_off | `[15:8]` | 8 / 4bpp の CLUT のずらし: 色 = `CLUT[(値 + clut_off) & 255]` |
| wl / hl | `[7:4]` / `[3:0]` | 幅と高さの log2 (3..8 = 8..256 テクセル) |
| base | 2 ワード目 `[20:0]` | テクスチャの先頭の SDRAM のワードアドレス。**テクスチャのワード数 (幅 x 高さ / 1 ワードのテクセル数) の倍数** |

- `TRI` は記録したときの `SET_TEX` を覚える (シーンの中で `SET_TEX` を変えてよい)
- テクセル (tu, tv) = (u >> 6, v >> 6) を幅・高さで**折り返す** (はみ出しは繰り返し)。uv の範囲は 0..1023.98 (10.6) なので、大きな繰り返しはホストが三角形ごとに
  幅の倍数だけずらして収める

**並び (SDRAM)**: 8 ワードのかたまり (テクスチャのキャッシュの 1 行) の並び。かたまりは左上から行ごと、かたまりの中も行ごと
(`raster.py` の `tex_index`。ホストのアップロードはこの並びで作る):

| 形式 | 1 ワードのテクセル | かたまり (幅 x 高さ) | かたまりの 1 行 |
| --- | --- | --- | --- |
| 16bpp | 2 (下位 16bit が偶数の u) | 4 x 4 | 2 ワード |
| 8bpp | 4 (u % 4 番目のバイト) | 4 x 8 | 1 ワード |
| 4bpp | 8 (u % 8 番目が `[31 - 4k -: 4]`) | 8 x 8 | 1 ワード |

```text
ワードの番号 (base からの差) = ((tv >> lbh) << (wl - lbw + 3)) | ((tu >> lbw) << 3) | ((tv & (かたまりの高さ - 1)) << lwpr) | ((tu >> s) & lwpr)
  s = 1 ワードのテクセル数の log2 (1 / 2 / 3)、lbw = かたまりの幅の log2、lbh = かたまりの高さの log2、lwpr = かたまりの 1 行のワード数の log2 (1 / 0 / 0)
```

**`CLUT_WRITE`** `[0x28, index(8), -, n(9)]` `data × ⌈n/2⌉`
CLUT の `index` から n 色 (1 ワードに 2 色、下位が先)。**すぐ**効くので、シーンの中では変えない (`END_SCENE` のときの CLUT で描く)。

**キャッシュ**: 64 行 x 8 ワードの直接写像 (8KiB)。外れると 1 回約 18 クロック止まる。同じテクスチャの近いテクセルは同じかたまりに入るので、
大きく縮小して貼る (遠くの面) と外れが増える。小さいテクスチャ・縮小したテクスチャ (ミップマップの代わり) を使うと速い

## 7. シーン (`BEGIN_SCENE` / `END_SCENE`)

**`BEGIN_SCENE`** `[0x25, flags(8), color(16)]`

| flags | 意味 |
| --- | --- |
| bit0 | 描く面を `color` で消してから描く (でなければ今の面の上に描く) |
| bit1 | Z を `0xFFFF` から始める (でなければ Z バッファ (`Z_BASE`) から読む) |
| bit2 | 最後の Z を Z バッファに書き戻す |

**`END_SCENE`** `[0x26]`: シーンの三角形をタイル (32 x 32、横 10 x 縦 8、一番下は 16 ライン) ごとに描いて、描く面 (と Z) に書く。
**終わるまで次のコマンドは待つ** (FIFO には積める)。

- シーンの中の `TRI` はその場では描かず、`END_SCENE` で投入順に描く。結果は、シーンの外で同じ順に描いたものと同じピクセル
  (消すシーンなら `CLEAR` + `CLEAR_Z` のあと)
- 消すシーンは画面全体を消す (クリップ矩形によらない)。描く面は `END_SCENE` のときの `DRAW_BASE`
- **シーンの中で 2D のコマンド (`FILL_RECT` など) を使わない** (三角形より先に描かれ、タイルの書き出しで消える)。2D は `BEGIN_SCENE` の前か `END_SCENE` のあと
- 上限: 1 シーン **4,096 個**、1 タイル **1,024 個**。超えた三角形は (そのタイルで) 描かず、`GPU_STATUS` のエラーが立つ
- **シーンの外の `TRI`** も描ける (中では 1 つだけのシーンとして、触れるタイルを描く面と Z バッファから読み、描いて書き戻す)。たくさん描くならシーンにまとめる

## 8. SDRAM の配置

ワードアドレス (32bit ワード) とバイトアドレス。SDRAM は 8MiB。

| バイト | 用途 |
| --- | --- |
| `0x000000`〜`0x03BFFF` | フレームバッファ 0 (240 ライン x 1KiB。`FB_BASE` の既定) |
| `0x040000`〜`0x07BFFF` | フレームバッファ 1 (`DRAW_BASE` の既定) |
| `0x080000`〜`0x0FFFFF` | パラメータバッファ (三角形のレコード、32 ワード x 4,096)。**使わない** |
| `0x100000`〜`0x14FFFF` | タイルのリスト。**使わない** |
| `0x380000`〜`0x3BBFFF` | Z バッファ (`Z_BASE` の既定。Z を読む・書き戻すシーンとシーンの外の Z の `TRI` が使う) |
| ほか | アプリケーション (テクスチャなど)。例: `0x280000`〜 (ワード `0xA0000`〜) |

テクスチャの先頭は 6 章の倍数の規則を守る。フレームバッファ・Z バッファは `FB_BASE` / `DRAW_BASE` / `Z_BASE` で動かせる。

## 9. 速さ

`clk_sys` は 63MHz。60Hz の 1 フレームは約 **1,050K クロック**。

| 項目 | おおよそのクロック |
| --- | --- |
| 三角形のビニング (セットアップ込み) | 1 個 約 200 |
| (三角形, タイル) の組の固定費 (レコードの読み込み、角の値) | 1 組 約 100 |
| ピクセル | 中のピクセル 1 個 約 1 (行ごとに約 2。三角形の外の行は飛ばす) |
| テクスチャのキャッシュの外れ | 1 回 約 18 |
| タイルの書き出し | 1 フレーム 約 66K (画面全体) |
| ビットストリームの切り替え | 約 1.7 秒 |

測った場面 (Verilator、1 フレーム): logo (239 三角形、Z) 290K、tunnel (237) 370K、room (190) 455K、
city (348、重ね描き約 3 倍) 960K。半透明は不透明と同じ速さで、Z で隠せないので重ねた枚数だけかかる (画面全体のテクスチャの重ね描きは 60fps で約 4 枚)。

**リンク**: 今のハーネス (SPI 8MHz、USB の RP2040 ブリッジ) は約 764KB/s で、60fps なら 1 フレーム約 3,200 ワード
(テクスチャ + Gouraud の `TRI` で約 300 個)。本番の HSTX は 37MB/s の見込み ([HARNESS2.md](HARNESS2.md))。

## 10. 制限

- 1 シーン 4,096 個、1 タイル 1,024 個 (超えた分は描かずエラー)
- 頂点は -512..+831 ピクセル (ガードバンド)。遠近補正なし (大きな面はホストが細かく割る)
- テクスチャは 8..256 の 2 のべき、16 / 8 / 4bpp。CLUT は 256 色 1 組 (シーンの中で変えない)。テクスチャの先頭はワード数の倍数
- 半透明は投入順 (順序に依存しない半透明はない)。ミップマップ・バイリニアはない (最近傍)
- 8bpp の面、`BLIT` 系、タイルの面・スプライト・Mode 7・音はない (VDP のビットストリーム)

## 11. 1 フレームの組み立て方

```text
起動: CONTROL = 0x08。テクスチャを UPLOAD (6 章の並び)、CLUT_WRITE
毎フレーム:
  BEGIN_SCENE (消す色、clear_z)
    不透明の三角形: SET_TEX → TRI ...   (Z を使うか、ホストが奥から手前に並べる)
    半透明の三角形: 奥から手前に
  END_SCENE
  (2D の HUD: FILL_RECT / DRAW_LINE など)
  SWAP
```

ホストの仕事 (`tools/harness/demo3d.py` が例): 頂点の変換、視錐台とガードバンドで切る、裏面を捨てる、頂点の明るさと霧、
環境マップの uv、Z を使わないなら奥から手前に並べる。Z を使わないと 1 三角形 3 ワード少ない。

## 12. 検証の手がかり

- `FRAME_CRC` (0x05〜): 表示したフレームの CRC-32。参照モデル (`gpu_model.py`) の CRC と比べれば、ピクセル単位で同じかが分かる
- シナリオ (`scenarios/gpu3d/*.json`): コマンド列と期待値。`make scenario SCENARIO=…` (Verilator)、`harness.py scenario …` (実機) で比べる
- `GPU_STATUS` のエラー: 上限を超えた三角形、ないコマンド
